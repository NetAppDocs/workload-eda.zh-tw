= 了解 Workload Factory for EDA 中的 Overview 儀表板
:allow-uri-read: 
:icons: font
:imagesdir: ./media/


[role="lead"]
概覽儀表板為 IT 管理員提供了一個集中監控多個 FSx for ONTAP 檔案系統上的 EDA 工作負載的位置。您可以使用它快速檢查系統運作狀況和使用情況，選擇新磁碟區或作業的放置位置，尋找可能需要移動的磁碟區或 SVM，以及了解何時需要增加容量或吞吐量。



[[overview]]
== 概況

概覽儀表板會收集與您設定的 AWS 認證相關聯之所有 FSx for ONTAP 檔案系統的 CloudWatch 指標。

其中包括：

* *叢集健康狀態*：頂端摘要會醒目顯示檔案系統中的延遲事件、SSD 使用情況、容量建議和 ONTAP EMS 事件。
* *叢集表格*：一個可搜尋的表格，顯示每個叢集的使用情況和效能。您可以篩選和排序資料、翻頁以及將其匯出為 CSV 檔案。


它可協助您：

* 放置新磁碟區並重新平衡工作負載
* 規劃容量或處理量擴充
* 大規模監控叢集健全狀況
* 就磁碟區放置做出明智的決策
* 識別接近容量限制的叢集




[[dashboard-components]]
== 儀表板元件



[[cluster-health-status]]
=== 叢集健全狀況

叢集運作狀況概覽會快速顯示您所選檔案系統的活動。只有當至少有一個 FSx for ONTAP 連結連接到您的檔案系統時，才會顯示此概覽。

健康狀態包括下列領域：

*延遲*:: 顯示在所選檔案系統中發現的延遲事件數量。此資訊僅在啟用延遲監控時顯示。
*SSD 容量管理*:: 顯示 SSD 使用率超過 80% 的檔案系統數量以及具有主動容量建議的檔案系統數量。這有助於您快速識別可能需要容量關注的檔案系統。
*ONTAP 事件*:: 顯示偵測到的 EMS 事件數量，按容量、可用性與保護以及安全性與其他類別進行分類。




[[clusters-table]]
=== 叢集表

叢集表提供了每個 FSx for ONTAP 檔案系統的詳細視圖，並依您目前所在的區域和 AWS 帳戶進行篩選。資料來源於 CloudWatch 指標。

使用此表可以：

* 識別接近容量上限的檔案系統（SSD 使用量欄）
* 將吞吐量需求與已佈建的吞吐量 SKU 進行比較（吞吐量使用量 P99 欄）
* 追蹤多個叢集的效能指標
* 檢查連結組態狀態（相關連結欄）- 每日驗證連線有效性
* 選擇多個叢集進行批次參數更新




[[ssd-capacity-management]]
== SSD 容量管理



[[management-modes]]
=== 管理模式

*自動化*:: Workload Factory 會在 SSD 使用量達到設定限制時自動增加更多 SSD 空間。它會自動處理此操作，無需手動操作。這對於偏好自動化管理的環境來說非常適用。
*建議*:: Workload Factory 會分析您如何使用 SSD，並建議何時增加容量。您可以查看這些建議並決定是否採納。這樣，您既可以完全掌控容量變更，又能從自動化分析中受益。
*無*:: 系統不會提供容量建議或執行自動操作。如果您想自行管理容量，請使用此選項。




[[capacity-recommendations]]
=== 容量建議

當 Workload Factory 處於 Automate 或 Recommend 模式時，它會自動檢查每個 FSx for ONTAP 檔案系統，並執行容量建議演算法。系統每 24 小時掃描一次，以確定是否需要調整 SSD 容量。

當識別出建議時：

* 您將根據 Workload Factory 的通知設定立即收到通知。
* 透過使用「上次 SSD 增加時間戳記」或「上次 SSD 增加描述」欄篩選叢集表，識別具有建議的檔案系統。
* 介面顯示目前具有有效建議的檔案系統總數。


該建議解釋了建議的變更及其背後的原因，例如：_我們建議您根據檔案系統的 SSD 使用模式增加 SSD 容量。_



[[ssd-management-parameters]]
=== SSD 管理參數

參數控制容量管理系統如何分析和處理您的 SSD 使用情況：

*臨界值* （10-90%）:: 觸發容量建議或自動化操作的 SSD 使用率百分比。例如，閾值設為 80% 表示當 SSD 使用率達到 80% 時，系統將執行相應的建議或操作。此設定在「建議」模式和「自動化」模式下均可使用。
*Lookback*（1-200 小時）:: 用於分析歷史 SSD 使用模式的時間段。更長的回溯期可為容量決策提供更多歷史背景資訊。僅在 Automate 模式下可用。
*提前* （1-200 小時）:: 用於預測未來容量需求的時段。預測時段越長，對未來容量成長的規劃就越長遠。僅在自動模式下可用。


您可以為每個檔案系統單獨設定這些參數，也可以使用批次編輯將相同的設定套用至多個檔案系統。



[[understanding-capacity-decision-points]]
=== 了解容量決策點

SSD 使用圖會標記系統何時提出容量建議或執行自動操作。這些標記顯示容量管理演算法隨時間推移的運作方式。

*建議決策點*:: 當系統偵測到需要更多 SSD 容量時，就會出現此提示。如果容量尚未增加，這些提示點可能每 30 分鐘出現一次。圖表會盡可能顯示每個決策點。如果選定的時間範圍過於密集，則會將這些點合併在一起。
*自動化決策點*:: 當自動化系統嘗試增加 SSD 容量時，就會出現這些提示。它們會顯示操作成功或失敗的情況。


使用 SSD 使用歷史圖表可以：

* 查看您需要多久更改一次儲存容量
* 決定自動化模式或推薦模式更符合您的使用習慣
* 發現反覆出現的儲存短缺問題
* 根據成長狀況規劃未來的儲存需求
* 調查自動化嘗試失敗的原因
